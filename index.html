YouTube Summarizer

Live demo Next.js Gemini 2.5 Flash

Веб-сервис суммаризации YouTube-видео: пользователь вставляет ссылку на ролик, сервис получает субтитры видео через сервис Supadata и на их основе формирует подытоженное содержание этого видео с помощью модели Gemini 2.5 Flash.

Реализовано

  • Разбор ссылок разных форматов (youtube.com/watch, youtu.be) с извлечением идентификатора видео.
  • Получение субтитров через Supadata API с таймаутом 30 секунд и поддержкой разных форматов ответа (строка или массив сегментов).
  • Промпт, требующий строгий JSON: краткое содержание (до 50 слов) и ключевые моменты с временны́ми метками.
  • Повторные попытки при перегрузке модели (ошибка 503) с экспоненциальной задержкой.
  • Защищённый JWT-токеном API-эндпоинт /api/summarize (часть системы аккаунтов) и служебный /api/status.
  • Юнит-тесты на Vitest и аналитика Vercel Analytics.

Реализовано, но не активировано в текущем демо

  • не активноРегистрация и вход через Supabase: 5 кредитов при первом обращении и списание 1 кредита за успешный запрос суммаризации.
  • не активноИстория суммаризаций пользователя в базе данных и отображение остатка кредитов в интерфейсе.

Функционал реализован в кодовой базе (Supabase Auth, таблицы profiles и user_summaries, проверка JWT в API), но в текущем демо намеренно отключён — чтобы наглядно показать работоспособность сервиса без регистрации. В самом интерфейсе это заявлено бейджами «Бесплатно», «Без регистрации», «Любой язык видео».

Технологии

Next.js 15 React 18 TypeScript Tailwind CSS 4 Radix UI Supabase (Auth + Postgres) Supadata JS SDK Google Generative AI — Gemini 2.5 Flash Vercel Vitest

Сервис в текущем демо работает без регистрации: вход в аккаунт и списание кредитов не активированы, чтобы можно было сразу проверить суммаризацию. Код системы аккаунтов и истории запросов остаётся в проекте и включается активацией соответствующих проверок.

LiveClasses AI Agent — Telegram-бот расписания трансляций

Telegram bot Cloudflare Workers Cron Triggers

По заданному таймеру агент выполняет действие и сообщает информацию в Telegram: раз в день он анализирует график бесплатных онлайн-трансляций на liveclasses.ru, забирает расписание трансляций к себе в базу данных, а дальше либо пользователь спрашивает в боте о трансляциях, которые ему интересны, либо бот сам присылает уведомление о начале трансляции за 15 минут до её начала.

Схема решения: Backend в облаке на Cloudflare по таймеру → Frontend в Telegram-боте. Пользовательского веб-интерфейса нет — весь фронтенд вынесен в Telegram-бота.

  • →

Реализовано

  • Ежедневный сбор расписания бесплатных онлайн-трансляций на «завтра» по Cron 55 20 * * *: очистка таблицы broadcasts и запись актуального графика.
  • Планировщик каждую минуту по Cron * * * * *: поиск трансляций, начинающихся ровно через 15 минут, и рассылка уведомлений всем подписчикам.
  • Хранение данных в Cloudflare D1: таблица broadcasts (название мастер-класса, время начала, автор, ссылка) и таблица users (chat_id подписчиков).
  • Telegram-бот как пользовательский фронтенд: приём обновлений через webhook и автоматическое сохранение chat_id при первом обращении.
  • Чат-бот отвечает на любые вопросы по расписанию: вопрос пользователя и контекст из D1 передаются в Gemini 2.5 Flash-Lite.
  • Служебная команда «тест» — присылает случайное напоминание о трансляции для проверки генерации сообщений и выборки из БД.
  • Конфигурация секретов и привязок: TELEGRAM_BOT_TOKEN, GEMINI_API_KEY, binding DB для D1.
  • Парсинг HTML расписания через cheerio: поиск блока «завтра» по заголовку расписания и извлечение названия, времени, автора и ссылки мастер-класса.
  • Ручные точки запуска для отладки и повторного прогона: /trigger-parse и /trigger-notify; локальная разработка через wrangler dev и ручной вызов Cron (/__scheduled).
  • Юнит-тесты на Vitest с пулом воркеров Cloudflare (@cloudflare/vitest-pool-workers) для логики работы с базой и ответами бота.

Технологии

TypeScript Cloudflare Workers Cloudflare D1 (SQLite) Cloudflare Cron Triggers Telegram Bot API (webhook) Gemini 2.5 Flash-Lite cheerio Wrangler Vitest + vitest-pool-workers

Парсинг расписания выполняется детерминированно, а LLM используется только для диалоговых ответов пользователю — это экономит запросы к модели и делает данные в базе предсказуемыми.

Kufar PC Monitor — мониторинг объявлений о компьютерах

Backend-only Cloudflare D1 Queues TypeScript

Kufar PC Monitor — сервис мониторинга объявлений на Kufar в категории «Компьютеры и системные блоки». Он регулярно собирает объявления, сохраняет их в собственной базе данных, извлекает из текстов характеристики компьютеров, формирует структурированное представление компонентов и в дальнейшем оценивает соотношение цены и характеристик («цена/качество»), а также отслеживает новые объявления и изменения существующих.

Проект ориентирован прежде всего на автоматизированный сбор и последующую аналитическую оценку предложений.

Задачи проекта

  • Регулярно получать объявления Kufar.
  • Сохранять их в собственной базе данных.
  • Извлекать из объявлений характеристики компьютеров.
  • Формировать структурированное представление компонентов.
  • В дальнейшем оценивать соотношение цены и характеристик («цена/качество»).
  • Отслеживать новые объявления и изменения существующих.

Реализовано

  • Извлечение характеристик ПК: CPU, GPU, RAM (объём и тип), SSD, HDD, материнская плата, блок питания и его мощность, корпус, кулер.
  • Нормализация названий комплектующих и ведение каталога комплектующих с оценкой производительности и стоимости на вторичном рынке.
  • Расчёт предварительной стоимости комплектующих и оценка completeness score, price score, risk score и final score с рекомендацией и перечнем причин.
  • Таблицы Cloudflare D1: listings, listing_components, component_catalog, price_observations, evaluations.
  • Хранение исходного текста объявления (raw_text) для повторного анализа и версионирование парсера через parser_version.
  • Отслеживание жизненного цикла объявления: first_seen_at, last_seen_at, status — объявления не удаляются при исчезновении с Kufar.
  • REST API для получения сохранённых объявлений и результатов оценки.
  • Набор локальных .mjs-скриптов для тестов, аудитов, backfill-операций и подготовительных расчётов по выгруженным данным.
  • Тестовый runner test_runner.mjs; проверка SQL и схемы локально через better-sqlite3; typecheck через TypeScript.

Технологии

Cloudflare Workers Cloudflare D1 (SQLite) Cloudflare Queues Cloudflare Cron Triggers TypeScript Wrangler better-sqlite3 локальные .mjs-скрипты test_runner.mjs

Публичной ссылки у проекта нет: он развивается как backend-сервис, поэтому решение о выборе оптимального варианта системного блока принималось на самостоятельной оценке выгруженных текстов объявлений — цены и комплектующие разнесены во внутренней таблице Cloudflare на составляющие — без разработки графической Frontend-части. Ключевые архитектурные решения MVP: детерминированный парсер вместо LLM на каждой операции, обычный HTTP-fetch вместо Browser Rendering, обязательное сохранение исходного текста объявления для повторного анализа.

Технологии проектов

Общие блоки технологий, которые переиспользуются между всеми тремя сервисами.

Cloudflare как backend-платформа

Workers (serverless-выполнение), D1 как SQLite-совместимая база, Queues для асинхронной обработки и Cron Triggers как таймер. Используется в Telegram-агенте расписания и в мониторинге объявлений Kufar.

ИИ-интеграции

Google Gemini 2.5 Flash — суммаризация субтитров YouTube; Google Gemini 2.5 Flash-Lite — диалоговые ответы Telegram-бота по расписанию. Supadata — источник субтитров видео.

Telegram как интерфейс

Telegram Bot API через webhook: бот принимает вопросы по расписанию, хранит подписчиков и рассылает уведомления о трансляциях за 15 минут до начала.

Данные и контроль качества

Схемы и запросы для D1/SQLite и Supabase Postgres, локальные скрипты аудита и backfill, собственные тестовые runner'ы (.mjs) и Vitest для юнит-тестов.

Среды разработки

Проекты разрабатывались в средах с AI-агентами: основная работа велась в VS Code, дополнительно использовались агентные среды OpenCode и Antigravity.

VS Code с расширениями

Основная среда разработки: VS Code с расширениями Cline, Kilo и другими — навигация по коду, терминал, работа с Git, просмотр диффов изменений и запуск задач вместе с AI-агентами прямо в редакторе.
